🎯 **Qué se pedía** Replicar en el ordenador de casa el mismo entorno de trabajo configurado previamente en el centro. Esto implica instalar las herramientas necesarias (Obsidian, Git y OBS), generar una clave SSH propia para este equipo y reconstruir la bóveda local (fuera de OneDrive) clonando todos los repositorios desde GitHub.

⌨️ **Comandos y pasos importantes**

- `git --version` — Comprueba que Git se ha instalado correctamente en el sistema.
    
- `ssh-keygen -t ed25519 -C "correo"` — Genera un par de claves SSH (pública y privada) exclusivo para el ordenador de casa.
    
- `cat ~/.ssh/id_ed25519.pub` — Muestra el contenido de la clave pública por terminal para copiarla y pegarla en GitHub.
    
- `git config --global user.name "Nombre"` / `user.email "correo"` — Configura la identidad global de Git para firmar los _commits_ hechos desde casa.
    
- `ssh -T git@github.com` — Verifica que la autenticación por SSH contra GitHub funciona correctamente.
    
- `mkdir -p RUTA_SOR/Boveda_SOR/00_Apuntes` (y `01_Practicas`) — Crea la estructura de carpetas local de la bóveda fuera de OneDrive.
    
- `git clone git@github.com:USUARIO/repo.git Nombre_Carpeta` — Clona cada repositorio remoto desde GitHub asignándole el nombre exacto de carpeta usado en el centro.

🤔 **Respuestas a las preguntas**

1. **¿Por qué clonas desde GitHub en vez de copiar con pendrive?** Porque en GitHub está la versión actualizada y centralizada de todos los repositorios junto con su historial completo (`.git`). Clonar garantiza que la copia de casa sea exactamente idéntica a la del centro y quede vinculada directamente al repositorio remoto para poder hacer `pull` y `push` sin conflictos.
    
2. **¿Por qué generas una clave SSH nueva en casa?** Por seguridad y buenas prácticas: las claves privadas nunca deben copiarse ni transportarse de un ordenador a otro. Cada equipo debe tener su propio par de claves registrado en GitHub (`Equipo Centro` y `Equipo Casa`), de modo que si pierdes o formateas un ordenador puedas revocar solo su clave sin afectar al otro.
    
3. **¿Dónde NO debe estar la bóveda?** Nunca debe guardarse dentro de carpetas sincronizadas en la nube como OneDrive (por ejemplo, una carpeta `Documentos` con el icono de nube), ya que OneDrive entra en conflicto con los archivos internos de Git y provoca duplicados o corrupción en el repositorio.
