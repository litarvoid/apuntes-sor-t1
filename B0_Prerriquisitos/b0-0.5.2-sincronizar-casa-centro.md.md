⌨️ **Comandos y pasos importantes**

- `pwd` — Verifica que la terminal está abierta dentro de la carpeta exacta del repositorio que queremos sincronizar (por ejemplo, `Trimestre_1`).
    
- `git pull` — Descarga e integra desde GitHub los últimos cambios hechos en el otro equipo antes de empezar a trabajar.
    
    Fase_0.5.2_Sincronizar_Casa_Centro.pdf
    
- `git add .` — Añade al área de preparación (_staging_) todos los archivos nuevos o modificados dentro de ese repositorio.
    
    Fase_0.5.2_Sincronizar_Casa_Centro.pdf
    
- `git commit -m "mensaje"` — Guarda una instantánea de los cambios en el historial local con un mensaje descriptivo.
    
    Fase_0.5.2_Sincronizar_Casa_Centro.pdf
    
- `git push` — Sube los _commits_ locales a GitHub para que estén disponibles desde el otro ordenador.
    
    Fase_0.5.2_Sincronizar_Casa_Centro.pdf

🤔 **Respuestas a las preguntas**

1. **¿Por qué NO se mete la bóveda en OneDrive si usamos Git?** Porque son dos sistemas de sincronización compitiendo por los mismos archivos. OneDrive sincroniza a medias la carpeta oculta `.git` y puede corromper el historial de Git, además de generar copias duplicadas en conflicto (como `fichero-MiPC.md`) y anular el propósito de `git pull`. La bóveda debe estar siempre en local y GitHub actúa como nuestra única nube.
    
    Fase_0.5.2_Sincronizar_Casa_Centro.pdf
    
2. **Escribe el ciclo diario de tres pasos.**
    
    1. **Al llegar al ordenador:** ejecutar `git pull` en el repositorio para bajar los últimos cambios del otro equipo.
        
    2. **Durante la sesión:** trabajar con normalidad en Obsidian editando o creando entradas.
        
    3. **Antes de irse:** ejecutar `git add .`, `git commit -m "..."` y `git push` en cada carpeta de repositorio donde se haya tocado algo.
        
        Fase_0.5.2_Sincronizar_Casa_Centro.pdf
        
3. **¿Qué problema puede aparecer si olvidas el pull al empezar?** Si modificas un archivo en un equipo sin haber bajado antes los cambios que hiciste en el otro, al intentar sincronizar puede aparecer un conflicto (`CONFLICT`) porque Git no sabe qué versión de las dos debe prevalecer.
    
    Fase_0.5.2_Sincronizar_Casa_Centro.pdf
